# 集成HUD（Integrated HUD）

## 翻译贡献 / Contributing translations

欢迎为模组设置与玩家面板提交翻译。**完整模板：[locales/en.json](locales/en.json)**；简体中文示例：[locales/zh-CN.json](locales/zh-CN.json)。

### 制作翻译文件

1. 复制完整的 `locales/en.json`，按目标语言代码命名，例如日语 `locales/ja.json`、德语 `locales/de.json`。
2. 将 `name` 改为该语言的本地名称，例如 `日本語` 或 `Deutsch`。
3. 仅翻译 `strings` 中每个键右侧的文字，保留键名、JSON 结构和数值范围等含义。文件使用 **UTF-8（无 BOM）** 保存。
4. 保持合法 JSON：使用英文双引号，不添加注释或末尾逗号；文字中的双引号写为 `\"`，换行写为 `\n`。不要提交重复键、未知键、空字符串或代码。暂未翻译的键可以省略，运行时会回退英文。

结构示例（仅作说明，请从完整模板复制）：

```json
{
  "name": "日本語",
  "strings": {
    "options.weapon_hud.label": "武器 HUD"
  }
}
```

### 提交与合并

1. Fork 本仓库，在自己的分支中添加 `locales/<语言代码>.json`，然后向本仓库提交 Pull Request。
2. 在 PR 中说明语言、语言代码以及是否已在游戏内检查；若已测试，可附设置界面或面板截图。
3. 维护者审核翻译、运行构建校验，并确认 MDL 返回的语言标识能匹配文件名；必要时在 `src/localization.lua` 中补充语言别名。
4. 检查游戏内字体、文本长度及布局后合并 PR，重新构建并发布模组。**仅合并 JSON 文件不会更新已经发布的 ZIP，也不能通过向已安装模组旁放置 JSON 来加载翻译。**

当前语言设置提供“跟随 MDL”、“简体中文”、“English”和“Русский”，可通过点击依次循环切换，默认跟随 MDL。自动模式下，无法读取 MDL 语言或对应翻译不存在时回退到英文。翻译范围为运行时设置菜单、选项说明和玩家面板文字；独立狙击准星工具、管理器安装选项及武器弹种缩写暂不包含在此翻译接口中。更多说明见 [locales/README.md](locales/README.md)。

### English guide

Copy the **complete [English template](locales/en.json)** to `locales/<language-code>.json`, such as `ja.json` or `de.json`. Set `name` to the language's native name and translate only the values in `strings`; keep all keys and the JSON structure unchanged. Save as **UTF-8 without a BOM**. Use valid JSON with no comments, trailing commas, duplicate or unknown keys, empty strings, or executable code. Escape quotes as `\"` and line breaks as `\n`. Missing keys fall back to English.

Fork this repository, add the translation on your branch, and submit a pull request. Include the language name/code and any in-game test results or screenshots. The maintainer will validate the file during the build, check MDL language-code matching (adding aliases if needed), and review font support and layout before merging and publishing a rebuilt package. Adding a translation to the repository does not update an existing release ZIP; placing a JSON file beside an installed mod does not load it.

The language setting currently cycles through **Follow MDL** (default), **Simplified Chinese**, **English**, and **Russian**. When set to Follow MDL, unreadable or unsupported MDL languages fall back to English (any future community translations added to locales/ will also be picked up automatically in this mode). This interface covers runtime settings and player-panel text, not the standalone sniper tool, mod-manager installation options, or weapon ammunition abbreviations.

当前版本：**0.9.3**。武器身份、弹药、热量和换弹状态改用 HD2 Data Hub；全部 HUD、数字和文字改用 MDL3.gui 和游戏菜单字体。载具数据及武器功能模式／射速保留经过约束的 GameSession 补充读取。保留独立开关、缩放、延迟面板位置。内侧蓄力圆弧已通过用户实机验证，整合包已通过基本构建检查。血条旁的队友强化仍有错位反馈，列表中的玩家／强化对应正常。

## 功能

- **小队强化图标**：调用 Hub `D.buffs()`，按 peer 与 `D.players(false)` 的成员逐人关联，包含自己；显示在彩色玩家标签左上方，避开麦克风。使用从当前游戏原生矢量资源转换的 20 种图标；确认未携带强化时绘制空心六边形，未取得成员数据时留空，未知强化显示带问号的轮廓。提供独立 MDL 开关，换场景或停用时清理。

- **武器 HUD**：准星右侧外侧圆弧显示弹匣余量或热量；弹匣武器下方显示“弹匣内余量 / 备用弹匣量”，热量武器显示百分比，换弹期间继续显示当前读取到的弹药／热量数据，不推算换弹进度。
- **蓄力进度**：蓄力时在弹药／热量圆弧内侧显示独立青色圆弧，不显示蓄力数字，不改变外圈和原有弹药／热量数字。直接读取 Hub 的 `weapon.charge` 或 `heat.charge`，热量型另检查 `heat.charging`；取消或发射后隐藏内圈；换弹不再强制隐藏，蓄力内圈仍由实际蓄力数据决定。加速步枪、磁轨炮、纪元、类星体与新星已参与实机验证；磁轨炮 0.7 平台保留真实比例，不将其强制归一为满圈。两圈随武器 HUD 整体缩放。
- **下挂弹种**：幺二、仲裁者和带下挂喷火器的武器在圆弧右侧显示当前选择的主枪／下挂弹种；通过主枪指向下挂对象的字段校验，不依赖开火或手部姿态。下挂启用时从关联对象读取装填弹量、备弹与换弹状态，切回主枪恢复 Hub 主枪数据；下挂数据暂不可用时不沿用主枪弹量。
- **模式与射速**：圆弧右侧显示解析得到的功能模式及射速设置；内置模式采用随包图标，其余已解析模式回退为文字。VG-70 额外显示自动／齐射／全射图标；其他武器不显示普通半自动／全自动，没有有效数据时不显示占位。
- **背包供弹**：优先使用 Hub 的备弹结果；供弹武器若缺少 `mags_backpack` 合并标记，使用本地 `backpack.count`，不足时查询 `D.backpacks()` 中身份对应的本地弹药背包。已有合并标记时不重复加算，不额外绘制背包面板。手持支援武器时提前维持背包接口租约，背包实体或计数可用状态变化时立即触发补充读取；同一角色生命周期内保留已确认的武器供弹类型，不因模式关联暂时缺失而等待重试。计数本身不缓存，仍以 Hub 当前数据为准；Hub 的采样与发布延迟不能由本模组消除。
- **乘员探头**：个人武器 HUD 在坦克驾驶位／炮手位、机甲内和 FRV 驾驶位隐藏；其他座位恢复显示，无论是否探头。此规则不受载具 HUD 显示开关影响。
- **FRV／坦克 HUD**：显示载具外形、座位占用和当前血量，血量数字字号为 0.8.1 的 75%，按最终字号测量文字宽度后手动居中，标记本地玩家座位；FRV 额外显示轮胎状态。新增喷火 FRV 前座适配：仅显示驾驶与副驾驶两个座位，后座机枪位不显示载具 HUD，血量与轮胎沿用 FRV 样式。
- **机甲 HUD**：统一整体机甲剪影，显示当前总血量，数字字号为 0.8.1 的 75%，按最终字号测量文字宽度后手动居中，并随血量变化调整颜色。
- **武器 HUD 缩放**：MDL 滑动条调整为 50%–150%，以准星中心为固定锚点整体缩放，载具 HUD 不受影响。
- **弹药数字大小**：独立滑动条将弹匣／备弹数字调整为 50%–150%，默认 100%，步进 5%；数字中心位置固定，与武器 HUD 整体缩放叠加。热量百分比、模式／射速、圆弧与载具 HUD 不受此项影响。
- **字体与启停**：全部数字和文字采用 MDL 的游戏菜单字体；支持 MDL 实时启停，由画布管理场景变化及停用清理。文字需要 MDL 原生界面服务正常运行。

每帧使用 `HD2Data.player_ammo()` 的当前 `weapon.entity`，根据 `ammo_type` 切换弹匣／热量样式。弹量、膛内弹处理、背包备弹及热量均以 Hub 返回值为准，不再使用姿态、滚轮、开火活动或学习缓存挑选手持武器。换弹 `reload.active=true` 时继续显示当前有效数据；未读到手持武器或有效弹药时不沿用另一把武器的数据。圆弧不显示换弹进度。

Hub 尚未提供模式和射速接口，也未提供手持实体 ID 到 GameSession 网络对象 ID 的直接转换。0.8.0 将两者混用，导致补充读取未命中；0.8.1 将它们分开：根据 Hub 确定的武器槽位，在本地拥有的网络对象中，校验类型／字段声明、携带状态、所有者、地面拾取引用和弹量／热量。只在完整检查后存在唯一候选时关联网络对象；多个候选不猜选。此关联仅提供模式、射速和供弹类型标记，不能覆盖 Hub 的手持武器身份、弹量或热量。

该补充读取不使用持枪姿态、滚轮或开火选枪。初次关联采用有预算的分批类型检查，可能稍后才显示模式；关联后复用并持续校验，避免网络同步慢一帧使开火中的模式反复隐藏。模糊匹配或未收录槽位仍可能不显示模式，日志的 `WEAPON_BIND` 会说明原因；这不是 Hub 提供了直接转换接口。原有学习文件仅读取此前的模式值和射速设置，不再使用或写入姿态关联。

武器圆弧、载具形状及延迟面板全部经 `MDL3.gui` 绘制。动态文字使用独立的较高层画布，模式图标转为随包部署的图片，不再以数百个小矩形绘制。字体跟随游戏菜单设置，中文覆盖范围取决于该字体。缺少原生字体服务时 MDL 可能仅显示图形，主 HUD 日志记录 `MDL_GUI_FONT_UNAVAILABLE`。图片资源需要管理器部署后重启游戏加载；仅在 MDL 库中热启动未部署的包不能加载图片。

## 喷火 FRV 前座支持（0.7.5）

喷火 FRV 使用独立网络类型，已从当前游戏实体定义及网络配置确认其 64 个字段声明与机枪型一致。新增精确类型和字段校验，沿用血量、轮胎读取及原绘制缓存，不做未知车型的结构猜测。

仅适配驾驶位与副驾驶位，界面只绘制两个前排座位，保留车身、当前血量和轮胎状态。后座机枪位仍参与本地座位识别以正确隐藏／恢复界面，但不绘制载具 HUD；原有武器 HUD 行为不变。普通和补给 FRV 的座位及绘制保持原样。

驾驶位使用占用位 2，副驾驶位使用位 4，机枪位使用位 1。独立 MDL 热加载测试项已由用户实机验证通过后整合，基础检查覆盖前座绑定、高亮、机枪位隐藏、切回前座、稳定绘制缓存与下车清理。

## 网络延迟（Hub 路线验证）

“延迟数字”默认开启，已有用户保存的关闭状态保持不变。屏幕左边缘、垂直居中显示本机到其他所有成员的 RTT，最多三人；房主和客机使用相同路线。列表强化可独立控制，延迟数字与列表强化均关闭时隐藏整个面板。当前项目统一依赖 Hub 0.6.0，安装要求见前置依赖。

只调用 `HD2Data.players(false)` 获取 `peer / slot / is_local` 基础名单，使用 `Network.ping(peer)` 获取秒数并转换为毫秒，每秒采样一次。不枚举远端对象，不调用网络对象字段，不启用小队详细读取、弹药 getter、事件、聊天或自定义探测。

0.6.4 实测发现 Hub 的 slot 与原生 R1／C2 等编号不一致，因此本版停止绘制 P 编号和对应颜色，暂时显示同一条 Hub 记录的玩家名。本版延迟面板使用 MDL 游戏菜单字体，按 UTF-8 字符处理名字；仅空名、无效编码或显示后重名时回退为完整 peer ID；这不是原生编号适配完成。日志记录本地 peer、房主 peer、Hub 槽位及名称，供后续核对。使用名字时，名单须与会话成员完全一致、peer 与 Hub 槽位唯一且本地身份一致；名单不完整、重复或与会话不一致时，全体回退为当前会话 peer ID，不借用旧名单名字。连续两次映射相同后才显示；采样后复核名单及任务阶段。身份不明不猜编号，RTT 无效显示 `--`。此数值不保证等于 F5 面板。

未启用 Hub 显示 `ENABLE HD2 DATA HUB`，Hub 未就绪显示 `WAITING FOR HUB`。已建立多人会话后即可尝试采样，不再要求本地角色进入地面任务；在驱逐舰配装、中途加入等待空投等阶段，Hub 暂未提供完整名单时使用 peer ID，名单就绪后切换为名字。进入／退出地面任务、身份标签来源变化时重新确认。会话名单仅含自己时，额外检查 `Network.connections()`；有效且未断开的连接以完整 peer ID 显示，标题改为 `CONNECTION RTT`，不把这些连接断言为队伍成员，也不附加未经验证的玩家名。正式多人会话名单优先，名单就绪后切换回 `LOCAL RTT`。已知远端房主但名单／连接尚未就绪时显示等待，而非 `SOLO`；没有远端证据时显示 `SESSION LIST: SELF`，只说明当前读取路径仅确认本地成员，不能据此断言目标房间无人。Hub 第一次调用返回空值属于正常情况；无有效 RTT 时显示 `--`，不伪造零延迟。

0.6.3 已实测可以正常匹配进入，0.6.4 已实测可显示 RTT，但原生编号错配。0.6.5 已由用户确认能显示完整玩家名。0.6.6 放开舰船阶段采样，0.6.7 取消菜单光标触发的隐藏，用户确认全队舰船时可见；0.6.8 的连接回退实测仍显示 SOLO；0.6.9 保留读取与过滤规则，取消误导性 SOLO 文案并增加原始返回诊断，尚不能判定是接口缺数据、调用异常还是过滤问题；后续仍需找到原生编号的可靠来源。不要同时部署旧测试包。

延迟面板不再根据鼠标光标隐藏：装备选择、ESC 和其他菜单打开时继续绘制和更新；武器与载具 HUD 的原有隐藏规则不变。无网络会话时清理读数，关闭延迟开关或停用模组时清理面板。加载阶段若渲染世界暂时不存在，只能等待可用后恢复；菜单合成层的实际可见性仍需实机验证。

### 中途加入诊断

0.7.3 在只能确认自己的会话阶段，每秒查询一次基本 Hub 快照以维持租约，输出变化或每 10 秒记录 `PING DIAG`：当前 session、本地 peer、GameSession 原始名单、Network.connections 原始结果／异常、各连接的 has_connection／is_broken 返回及过滤信息、会话房主、Hub 就绪状态、任务 epoch／in_mission、本地玩家及小队基础字段。不会扫描远端对象，不读取弹药 getter，也不会对未确认 peer 测量 Ping。日志只用于确认中途加入实际能取得哪些数据，不把已有的 SOLO 日志当成“Hub 也没有队友”的证据。

## 延迟面板字体与大小

标题、玩家名和数字改用 MDL3.gui 原生文字，跟随当前游戏菜单字体；按完整 UTF-8 字符截短长名字，保持名字与 peer 对应，不保证覆盖所有 emoji。

MDL 增加独立“延迟面板大小”滑动条，范围 50%–150%，步进 5%，默认 100%。标题、名字、数字、行距、列距与阴影整体等比例缩放，默认位于屏幕左边缘和垂直中心；武器和载具缩放不受影响。标题右边缘下方绘制连续纵向分界线，左侧为名字，右侧为延迟（如 200ms）。名字超过列宽时只绘制能放下的完整前缀字符，不缩小字体，不切断 UTF-8 字节，也不改变底层名字与 peer 的绑定。分界线、列间距和全部文字随面板整体缩放。旧 MDL 菜单接口不可用时提供数值调整项。

MDL 新增两个独立位置滑动条：

- **延迟面板横向位置**：0–100，默认 0；0 靠左、50 居中、100 靠右。
- **延迟面板纵向位置**：0–100，默认 50；0 顶部、50 垂直居中、100 底部。

位置按屏幕可用区域百分比调整，步进 1；边缘位置预留面板尺寸，避免滑到屏幕外。标题、名字、延迟和分界线一起平移，不改变相对布局；与面板大小独立保存，修改后即时生效。旧版没有位置设置时保持左侧贴边、垂直居中。菜单滑动条不可用时提供相同范围的数值调整项。

本版运行包不再包含 Monocraft 或 Fusion Pixel 字形页；旧字库及生成工具已移入本地开发记录；历史版本和许可仍可从 Git 历史查看。

## 独立开关

在 MDL 的集成HUD详情／设置中分别调整“武器 HUD”“FRV HUD”“坦克 HUD”“机甲 HUD”，默认均开启。标签不再使用可能缺字的全角斜线。更改立即生效，并由 MDL 保存。设置界面附带提示：局内热切换后，可能需要上下车或武器开火刷新状态。武器开关同时控制步行及车内个人武器圆弧；其余三个开关仅控制对应载具界面，关闭一种不影响其他类型。

旧版“载具／机甲 HUD”关闭设置会迁移为三个开关均关闭。所有载具类型关闭时停止共享载具模块；只关闭部分类型时保留共享识别，以便其他类型仍能正常显示。整个模组停用仍会关闭全部界面。

## 武器 HUD 大小

在 MDL 的集成HUD设置中拖动“武器 HUD 大小”：范围 50–150，单位为百分比，步进 5，默认 100。圆弧、数字、图标及间距整体等比例缩放，固定准星中心锚点，载具与机甲 HUD 不受影响。退出设置界面即可看到新尺寸，无需开火刷新。滑动条使用 MDL 内置的 Mod Options Menu 兼容接口保存数值，不需要另装 MOM；若该接口关闭或不可用，则提供同范围的数字调整项。

### 弹药数字大小

MDL 设置中新增“弹药数字大小”滑动条：50%–150%，默认 100%，步进 5%。仅调整弹匣余量、斜线及备用弹匣量这一整行的字号，以该行中心为锚点；圆弧、武器模式及射速保持原样。与武器 HUD 整体缩放叠加，例如整体 150%、数字 150% 时，数字为原始大小的 225%。热量百分比不受独立数字滑动条影响。设置保存并即时刷新，旧配置默认保持原有字号；滑动条接口不可用时提供同范围数值调整项。

## 构建

需要 Python 3.10+ 和本机合法安装的游戏。Python 及依赖仅用于构建。

```powershell
python -m pip install -r requirements.txt
python tools/build.py --game-root "D:\steam\steamapps\common\Helldivers 2"
```

默认输出到 `dist/`，可使用 `--output-dir` 指定其他目录。构建器核对游戏版本及 PE 指纹，进行 Lua 5.1 编译、有限武器／座位／血量／启停模拟和包体完整性检查；不自动部署，不生成 sha256 侧车文件。`VERIFICATION.json` 中的哈希用于记录构建输入；`runtime_verified=false` 表示构建器自身未运行游戏，它不代表构建器进行过实机测试。


普通构建从已署名的 NarrowHUD 源文件中提取字段／类型及射速种子，仅将精简补充元数据打包；不运行或打包其完整识别器。`tools/mdl_images.py` 根据已保存的模式图标几何生成 MDL GUI 使用的 RGBA 贴图、mipmap 和材质资源，与 Lua 合并为一个补丁；不复制 MDL 运行时代码。Pillow 用于构建图片，玩家无需安装。

## 小队强化验证（0.8.4）

强化内容只使用 Hub 的基础名单与逐成员强化接口，血条行号另由受约束的 player/index 查找确定，不使用全队增强剂数组来猜每个人的选择，也不以返回数组的顺序关联图标。每条强化按 peer 与名单校验，重复 peer、槽位冲突或本地身份冲突时清空本轮展示。图标只在地面任务、无菜单光标时显示，每 0.2 秒查询缓存；原生血条独立于 MDL，0.8.5 当前布局已通过用户实机验证；其他原生 HUD 缩放或安全区设置可能需要校准。

默认以 1080 高坐标定位：本地玩家图标在自己的底部血条标签左上方，其他成员按已校验的原生 player/index 降序放入上方队友行；编号含义与实际血条对应待实机确认。Hub 槽位不等于原生彩色标签编号，本版不绘制或推断 R1/C2 等编号。图标中心、字号和行距在 `layout/boosters.json`，原生 HUD 的缩放、安全区或排序若不同，需根据实机截图校准。日志的 `BOOSTER` 记录 peer、名字、槽位、强化及绘制中心，便于逐人核对。

构建从当前合法安装游戏的 `content/ui/shared/resources/generated_icons/booster_icons` 读取并校验原生矢量资源，通过 Windows PowerShell/WPF 原样渲染 Path、颜色、描边为小图片，再转为 MDL GUI 纹理；不重画强化图案，不分发整个原始 XAML 或 MDL/Hub 代码。仅构建需要系统自带的 Windows PowerShell/WPF；玩家无需额外安装。无强化的空心六边形由模组绘制。
